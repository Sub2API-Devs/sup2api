# 2026-11-04 核查：逻辑是否完整复原、是否是完整可读的项目

用户要求核查两件事：阅读树是否完整复原了 CLI 的逻辑，以及它是不是一个人能读懂的完整项目。本次核查分三路做：

1. 从 HEAD 干净检出，从零安装、构建、对拍，证明入库的内容自成一个完整项目。
2. 新写声明级比对，逐个声明拿阅读树和官方字节比较，证明逻辑完整。
3. 请一个没参与过本项目的子代理（sonnet）独立抽样阅读，评价可读性。

## 1. 干净检出

做法：`git archive HEAD next/plugins/ccgateway/cli-reverse` 解到 `D:\.cc-verify\clean-1104`，然后：

1. `npm ci --ignore-scripts`
2. `node reconstructed/build.mjs`
3. `node tools/verify/compare.mjs original reconstructed/dist`

问题：按 README 的步骤执行 `npm ci --ignore-scripts` 后，bun 包的 postinstall 不会运行，`node_modules/bun/bin/bun.exe` 只是占位文件，构建直接报 `spawnSync … UNKNOWN`。原工作目录能用，只是因为以前装过一次。

修正：`tools/build/build.mjs` 和 `tools/verify/run.mjs` 的 Bun 查找改为先试 `node_modules/bun/bin`，跑不起来再试 `node_modules/@oven/bun-*/bin`。

修正后的结果：

- 构建 0 错误，2,650 个文件，耗时 59 秒。
- `--version` 输出 `2.1.316 (Claude Code)`。
- 对拍 **98/98**，其中 `tty-continue` 第一次没对上，重跑后一致。

## 2. 声明级等价（`tools/verify/decl-equiv.mjs`）

之前的论证链有一个缺口：

- 已有证明：α 校验证明 `original ≡ runnable`；规范形校验证明 `runnable ≡ 去压缩后的 runnable`。
- 缺口：阅读树是在这之后把声明拆进几千个文件，并加上导入、`export`、`deferInit` 包装生成的。这一步只有两种检查：`readable-check` 只看出处标记在不在，不比内容；98 个运行场景只覆盖它们走到的路径。

新工具的做法：

- 对每个声明，取出出处标记后面的语句，和官方模块里同一字节区间的语句对比。
- 两边先做同样的处理：
  1. 还原阅读树布局：去掉 `export`；把 `deferInit` 拆开，`var X;` 加延迟的 `X = …` 合回 `var X = …`，解构同理；`var X = class X` 还原为 `class X`；去掉文件末尾的 `runDeferredInits`。
  2. 用 `deminify.mjs` 的 `canonicalize` 求规范形。
  3. 每个绑定按它在声明里首次出现的顺序编号。改名必须一致：原来是同一个绑定的仍是同一个，原来不同的仍不同。
  4. 全局名、属性名、字面量和语法结构原样保留。
- 有几处差别不比：`import()` 和 `require("./…")` 的模块路径（这由构建和运行对拍检查）、`var/let/const` 的种类（另外计数）、空语句、属性键写成 `0` 还是 `"0"`、同一运算符的 `&&` 和 `||` 怎么分组。

结果：

| 项 | 数 |
|---|---|
| 官方声明 | 81,667 |
| 一致 | 81,662 |
| 不一致 | 5（全在第三方包，见下） |
| 官方顶层语句没有着落 | 0 |
| 阅读树多出、不对应官方的声明 | 0 |
| 未标记语句 | 88，全是胶水代码：`beginDeferredInits`、`build.mjs`、`runtime/`、worker |

5 处不一致：

- `@modelcontextprotocol/client` 有 3 处：官方是 `var X = class e {…}`，阅读树按 npm 源码写成 `class X {…}`，只在提升和暂时性死区上有差别。
- `@smithy/core` 有 1 处：`export default` 被延迟了。
- `marked` 有 1 处：正则 flags 官方是 `ig`，阅读树是 `gi`，只影响 `toString()` 的输出。

比对器本身调了 4 轮。前几轮出现的不一致，逐类看过，都是比对器还没覆盖的合法写法，例如多变量延迟初始化、动态导入路径、函数名被同名局部变量遮蔽、标签名。没有发现逻辑被改动或丢失。

| ARCHITECTURE 说手动 `/compact` 走 `compactConversation` | 属实：316 的 `/compact` 走 `compactViaReactive`（复用预计算摘要或走反应式压缩） | 已改 ARCHITECTURE.md 和 handbook/query.md |

| 大文件：print.js 19k 行，mcp/client.js 16k 行 | 属实：声明不多，是单个函数变大了 | README 已列入已知限制 |
