## 4. 尚未完成、未验证与明确边界

接续的权威细项见 [协议审计](implementation/COMPLETION-PROTOCOL-AUDIT-2026-10-09.md) 与 [原始要求/全栈审计](implementation/COMPLETION-SCOPE-AUDIT-2026-10-09.md)。本节不将当前门禁自动认定为永远不能做。

1. **多服务器 dynamic MCP**：补稳定目录、server/tool 联合身份、历史位置、错误/资格及续聊/冷导入/回退的合同与实验；多个 pinned 已支持不代表 dynamic 已支持。
2. **forced deferred / mixed any / helper**：需要发现且执行仍满足选择约束的设计；不能改成 auto 搜索后重发冒充 forced。
3. **已登记隐藏 helper 链的组合**：资源、credit、MCP、context/compaction、assistant continuation 等仍有真实门禁；OpenAI 转换链与 helper 的组合也要单列。单项通过不等于组合保真。
4. **inline＋内部 search 的非普通 custom 场景**：native/server/typed/MCP、safeguards、signed compaction 等需合同和新验证；普通 custom 支持范围不可外推。
5. **跨模型 fallback＋compaction 用量归属**：缺可靠官方实际模型/attempt 归属时拒绝猜价；要补证据或明确产品边界，不能模拟免费或静默丢隐藏用量。
6. **未知 beta/body 策略**：源码存在 unknown beta 默认 ignore、可选 unknown field ignore；并非“任意未支持语义都明确拒绝”。需读取实际保存策略，设计严格默认/语义未知字段处理和前后端兼容。当前没有生产配置取证，不宣称生产因此失败。
7. **运行态能力展示**：后端已有 helper transport schema=1 与 payload v1/v2；UI 仍缺 payload versions 单独呈现/校验。是展示欠账，不是后端协商未实现。
8. **真实资格及广泛组合验收**：code execution/PTC/Skills 的公开 200 中含 `tooltoo_many_requests`，只证明正确返回，未证明成功执行产物；Advisor、fast、长 context/compaction、fallback credit 发行/兑换/退款等也缺完整成功/费用资格闭环；diagnostics 有 refusal/cache miss，未证明 cache hit；超长上下文、取消并发、macOS、跨账号资源归属仍不能全勾通过。原要求逐功能×入口×#21/#22的真实矩阵未全满足，生产新账号冷调度亦未全验。
9. **独立产品端点**：持久 Responses stored IDs/background、Batches 不因无状态转换而具备；需要独立资源、权限、状态机。跨 issuer 文件/container/Skills/credit/diagnostic ID 不能猜测继承。
10. **上游模型限制**：Sonnet 4.6 inline system 不支持、普通文字 prefill 等不是网关能伪造支持的能力。HTTP 200 refusal 是正常模型返回；真实上游错误与 safeguards 不能伪装成功或吞掉。

当前不提供“完成百分比”：37 个功能与 8 个端点不是等权任务，功能已实现、组合受限和真实资格未验证必须分别记录。
