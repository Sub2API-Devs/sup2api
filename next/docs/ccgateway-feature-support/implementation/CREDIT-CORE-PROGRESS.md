# Core credit integration

2026-10-08, working tree only. This is implementation and isolated evidence, not a deployed or real-provider redemption claim.

The public Messages request first authenticates its group/model and any provider resources. Credit ownership is stored independently from API key identity, using user/group, original account/principal/generation, a token hash and allowed prompt digests. The gateway does not store the token or the original prompt in this registry. Known CC credits are pinned to their account; changing a platform key does not change ownership. Non-CC Anthropic transport retains its original provider-token path.

Before dispatch, the gateway strips client-supplied private credit headers, verifies current issuer identity, then grants tracking and (for a registered redemption) its exact token hash. Once a request carrying a token is dispatched, neither rate-limit nor transport classification may automatically move it to another account or retry it. A failed identity-only eligibility probe for a new unbound operation can try a different account before any model invocation.

Tracked credit responses share the bounded stateful response preparation path. Original JSON/SSE usage is consumed before custody registration. When resources are present, public resource and skill/version IDs are rewritten before computing the client-visible credit continuation claim. Worker Ready must match the actual token hash and actual issuer headers. Ordinary refusal remains HTTP200; a storage fault is recorded separately as gateway_credit_storage. Worker storage failure carries the original internal Message and usage with an authenticated failure header; the core withholds its unregistered token and sends the explicit gateway fault after preserving observed usage.

The original credit request body must stay exact except for documented non-prompt parameters. A pending programmatic-tool echo can omit a newly returned container only after its stored exact prompt claim is verified: adding that container would violate the provider's credit protocol. Worker independently proves its original wire snapshot and ended-attempt ledger. Best-effort without such a verified prompt does not receive this exemption.

Tests include actual HTTP JSON/SSE custody, unchanged normal refusal, owner/group and key rotation, source-account pinning, current issuer checks, changed prompt, expiry, resource conflicts, private header stripping, missing Ready, storage failures preserving 11 input/7 output usage, no automatic retry after 429, and a new operation skipping an ineligible account before the single model call. The independent review adds ordinary non-CC passthrough and strict/object/best_effort dispatch cases. PostgreSQL ownership tests remain a separate Linux checkpoint.

Sources: [Fallback credit rules](https://platform.claude.com/docs/en/build-with-claude/fallback-credit), [SDK object parameter](https://raw.githubusercontent.com/anthropics/anthropic-sdk-python/main/src/anthropic/types/beta/beta_fallback_credit_token_param.py). Do not reuse the earlier string-only evidence as proof of every mode.
