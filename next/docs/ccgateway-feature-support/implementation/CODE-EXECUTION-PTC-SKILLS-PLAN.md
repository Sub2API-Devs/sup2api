# Code Execution, PTC and Skills implementation plan

Evidence date: 2026-10-08. This fifth-batch design follows checkpoint `bfcbc3b4203cb664e53db305da4fadaecda67106`; no resource implementation is claimed by this document. Core Files ACL/storage is a separate owner. Worker owns protocol/CLI transport, not public authorization policy.

## Versions and request surface

Current code-execution versions are `20250825`, `20260120`, `20260521`; none requires a new beta opt-in. The latest two add persistent REPL/PTC; `20260521` changes the advertised Python cell time limit, not the runtime. Legacy `20250522` remains a distinct Python-only contract and must not be silently upgraded. Model support must use `capabilities.server_tools.code_execution.supported`; PTC capability is a separate check. [Official code-execution guide](https://platform.claude.com/docs/en/agents-and-tools/tool-use/code-execution-tool).

Tool definition: `type`, fixed `name:code_execution`, optional `allowed_callers`, `cache_control`, `defer_loading`, `strict`. The current SDK caller enum also contains `code_execution_20250825`; PTC guidance focuses on interchangeable `20260120`/`20260521` and returns caller `20260120`. Preserve the declared version; verify legacy caller combinations separately rather than treating every enum value as equivalent behavior. [Latest tool schema](https://raw.githubusercontent.com/anthropics/anthropic-sdk-python/main/src/anthropic/types/beta/beta_code_execution_tool_20260521_param.py), [legacy tool schema](https://raw.githubusercontent.com/anthropics/anthropic-sdk-python/main/src/anthropic/types/beta/beta_code_execution_tool_20250522_param.py).

Top-level `container`: string ID, null, or object `{id?:string|null, skills?:array|null}`. Skills contain required `type:anthropic|custom`, `skill_id`, optional `version`; response container contains `id`, `expires_at`, optional resolved skills with version. User `container_upload` blocks contain `file_id` and optional cache control. These IDs require ownership resolution before provider dispatch. [Container union](https://raw.githubusercontent.com/anthropics/anthropic-sdk-python/main/src/anthropic/types/message_create_params_container_param.py), [container parameters](https://raw.githubusercontent.com/anthropics/anthropic-sdk-python/main/src/anthropic/types/beta/beta_container_params.py), [skill parameters](https://raw.githubusercontent.com/anthropics/anthropic-sdk-python/main/src/anthropic/types/beta/beta_skill_params.py), [upload block](https://raw.githubusercontent.com/anthropics/anthropic-sdk-python/main/src/anthropic/types/beta/beta_container_upload_block_param.py).

## Exact response/history union

Keep these provider blocks distinct from local Bash/Read/Edit and client tools:

- `server_tool_use` names `code_execution`, `bash_code_execution`, `text_editor_code_execution`; preserve id/input/caller/cache control. A single top-level code-execution definition authorizes these documented subtools, not arbitrary server names. [Call schema](https://raw.githubusercontent.com/anthropics/anthropic-sdk-python/main/src/anthropic/types/beta/beta_server_tool_use_block_param.py).
- `code_execution_tool_result`: `tool_use_id`, content union of `code_execution_result`, `encrypted_code_execution_result`, `code_execution_tool_result_error`. Plain results carry stdout/stderr/return_code and output-file entries. Encrypted results carry encrypted_stdout instead of stdout, plus stderr/return_code/files; never decrypt or rewrite the opaque value. [Result union](https://raw.githubusercontent.com/anthropics/anthropic-sdk-python/main/src/anthropic/types/beta/beta_code_execution_tool_result_block_content.py).
- `bash_code_execution_tool_result`: result or error. Result contains stdout/stderr/return_code plus `bash_code_execution_output{file_id}` entries. [Bash union](https://raw.githubusercontent.com/anthropics/anthropic-sdk-python/main/src/anthropic/types/beta/beta_bash_code_execution_tool_result_block_param.py), [bash output](https://raw.githubusercontent.com/anthropics/anthropic-sdk-python/main/src/anthropic/types/beta/beta_bash_code_execution_output_block_param.py).
- `text_editor_code_execution_tool_result`: error, view, create or str_replace. View has content/file_type and nullable line metadata; create has is_file_update; str_replace has nullable lines and old/new ranges. [Editor union](https://raw.githubusercontent.com/anthropics/anthropic-sdk-python/main/src/anthropic/types/beta/beta_text_editor_code_execution_tool_result_block_param.py), [view](https://raw.githubusercontent.com/anthropics/anthropic-sdk-python/main/src/anthropic/types/beta/beta_text_editor_code_execution_view_result_block_param.py), [create](https://raw.githubusercontent.com/anthropics/anthropic-sdk-python/main/src/anthropic/types/beta/beta_text_editor_code_execution_create_result_block_param.py), [replace](https://raw.githubusercontent.com/anthropics/anthropic-sdk-python/main/src/anthropic/types/beta/beta_text_editor_code_execution_str_replace_result_block_param.py).
- Error codes include invalid_tool_input/unavailable/too_many_requests/execution_time_exceeded; Bash additionally output_file_too_large and editor additionally file_not_found/error_message. Keep a tool error inside HTTP 200 as an ordinary result; do not synthesize a gateway failure. [Bash error](https://raw.githubusercontent.com/anthropics/anthropic-sdk-python/main/src/anthropic/types/beta/beta_bash_code_execution_tool_result_error_param.py), [editor error](https://raw.githubusercontent.com/anthropics/anthropic-sdk-python/main/src/anthropic/types/beta/beta_text_editor_code_execution_tool_result_error_param.py).

## PTC continuation contract

`tool_use.caller` is direct or a code-execution caller with `tool_id` bound to its outstanding server call. A paused programmatic turn requires the same owned container, complete history/catalog and all pending tool results in one user message. That message must contain only tool_result blocks; their content is text/string only. MCP connectors and browser/computer toolsets cannot be called programmatically. Strict tools, forced programmatic tool_choice, disable_parallel_tool_use and cyclic schemas have documented constraints. `allowed_callers` is guidance, not an authorization boundary. [Official PTC guide](https://platform.claude.com/docs/en/agents-and-tools/tool-use/programmatic-tool-calling), [caller schema](https://raw.githubusercontent.com/anthropics/anthropic-sdk-python/main/src/anthropic/types/beta/beta_server_tool_caller_20260120_param.py).

Implementation: extend the existing server ledger with container-scoped pending PTC children; preserve source caller IDs through client tool name mapping. Reuse API terminal control and exact history alignment. Do not resume programmatic calls on a different account/container, recreate a missing container silently, or invoke client tools inside Worker. Native CLI JSONL preservation needs real probes for every union branch, including mixed direct/PTC/server calls, repeated pause, encrypted results, fork and cold import.

## Skills and resource identity

Built-in pptx/xlsx/docx/pdf run inside provider code execution, not CC local plugins. Current standard Messages examples do not require old skills beta headers. Custom skill IDs and versions belong to an issuer/workspace and require the same ACL machinery as Files; `latest` must be resolved without changing the returned version. [Skills quickstart](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/quickstart), [resolved skill schema](https://raw.githubusercontent.com/anthropics/anthropic-sdk-python/main/src/anthropic/types/beta/beta_container_skill.py).

Core resolves public resource IDs to provider IDs plus PrincipalID/Generation/account. Worker returns stable issuer evidence and performs only the fixed authorized provider operation. Persist resource generation before issuing identities. Revalidate actual issuer after controlled authorization changes; preserve generation for verified same-issuer reauthorization and ordinary refresh. Rotate when issuer changes, or the explicit managed API-key epoch changes; do not couple resources to diagnostics login epochs or runtime/network revisions. OAuth identity must derive from authenticated account+organization/workspace facts, never token hashes. API-key mode requires an explicit managed issuer identifier and epoch; unknown issuer means resource operations are unavailable. Audit owner defines the durable resource ACL/migration contract.

## Worker resource carrier

Internal prefix: `/_ccgateway/resources`, followed only by a fixed Files/Skills route matrix. Worker API key authenticates core transport. No caller-selected host, scheme, redirect target or arbitrary API path. Files upload/download bodies are binary/multipart with 512 MiB hard cap, configurable lower cap and a global concurrent spool budget; provider enforces its own limit. Content-Length rejection precedes spooling, streaming upload/download enforce the same cap, cancellation removes spool files.

Use one no-session-persistence CLI bootstrap and the existing main nonce/lease attribution. Rewrite its first attributed model request to the selected resource method/path/body while retaining CLI-generated upstream authentication. Capture the actual provider status/headers/body, cancel CLI immediately and block all model/auxiliary/second resource calls. Never make a paid model request before the resource operation. Do not export OAuth to core; do not enter HistoryCache/message ownership. Resource response headers use the shared safety rules plus explicitly needed content metadata, never authentication/cookie headers. `/_ccgateway/resources/identity` exposes only stable issuer digest and generation.

## Reuse and remaining implementation gates

Worker can reuse RequestPlan/main attribution, server ledger, response envelope extensions (container already registered), exact JSON-number restoration, registered omissions, safe HTTP facts, terminal observer and generation lifecycle. Add focused code-execution union and resource-plan modules; avoid adding execution logic to the installed plugin. Core reuses managed SSH transport and the audit owner's ACL store. Provider-created output file IDs must be registered before exposing public IDs; parse only registered file-bearing protocol paths, never scan arbitrary tool input strings.

Usage must preserve complete nested maps and iterations. The code-execution guide shows `usage.server_tool_use.code_execution_requests`; the fetched SDK `BetaServerToolUsage` currently lists only web fields, so typed whitelisting would lose an official field. Execution pricing is time-based when not waived by eligible web tools; request counts do not prove execution seconds. Do not infer hourly provider cost from count, HTTP latency or token usage. Expose observable metrics and require explicit billing policy/source evidence before charging additional execution fees. [Pricing/usage section](https://platform.claude.com/docs/en/agents-and-tools/tool-use/code-execution-tool#usage-and-pricing), [SDK server usage](https://raw.githubusercontent.com/anthropics/anthropic-sdk-python/main/src/anthropic/types/beta/beta_server_tool_usage.py).

Validation order: isolated fixed resource transport with zero model calls; issuer rotation and foreign-ID rejection; every response union JSON/SSE and numeric fidelity; paired server/client/PTC histories and container expiry; Files output/download/cleanup; built-in then custom Skills. Finally controlled real provider calls with explicit provenance/cost, without changing existing account containers or authorization state.
