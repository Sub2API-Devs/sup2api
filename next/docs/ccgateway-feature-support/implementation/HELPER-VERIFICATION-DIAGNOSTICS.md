# Helper 预派发身份/能力失败的安全诊断

候选未提交/未部署。由两次真实503定位问题触发，线上仍保持原泛化响应；engine修复由另一作者负责。

核心新增 RuntimeVerificationError，仅携带固定stage（requirement/capabilities/policy/identity/unknown）、固定class、HTTP状态和严格单值ASCII请求ID。RequestID仅来自实际Worker HTTP response `request-id`，日志明确source=response_header:request-id；缺失/多值/控制字符/超128字符均省略，不从客户端header或metadata猜造。内部cause通过Unwrap保留供既有typed资格判断，Error()自身不展开cause。

只在helper预派发失败路径记录一次结构化slog，绑定核心真实RID/account，不记录请求正文、provider profile、principal/generation、令牌、完整URL或任意上游message。客户端response仍原泛化503。capability404现在可内部区分missing_route；identity非200按状态记固定类别，不把不可信文本变成资格。

ResourceTransport.Identity仍只对精确503 + `type:error/error.type:resource_identity_unsupported`允许既有Unsupported资格语义；读取至多8193字节并拒超8192，只读一次、不再读取原body用于日志。其他错误不因为文字相同而跳号。实际响应200但不合法身份文档为invalid_document，不泄露原值。

测试覆盖timeout/cancel/未知cause不泄漏、阶段包裹不修改原error、HTTP请求ID缺失/重复/非法/过长、精确issuer资格和文本伪造否例、日志仅一条且没有cause/假WorkerRID。定向ccgateway1.934s、gateway2.795s通过，两包vet通过；既有HelperCustody资格/固定链矩阵同时通过。已交audit_code_beta独立审查，未运行新生产请求。

独审通过：新增不允许Read的响应body验证诊断包装不二次读取、普通Unavailable含unsupported字样不改变资格、重复RID及未知stage不泄漏；ccgateway2.021s、gateway日志1.132s及两包vet通过。Root复核diff；脱敏证据脚本两项离线合成测试0.014s再次通过。本检查点只提交推送，不把它当线上已更新。
