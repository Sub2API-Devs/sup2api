# CCGateway 请求日志分级

2026-10-23 用户提出，同日确认第 7 节全部按建议：默认摘要；摘要 7 天 / 128 MiB；完整只能选 1/4/24 小时、到期回到摘要；现有完整日志自然过期；摘要保留最多 256 字符错误文字。

## 1. 现状

每个账号的 Worker 在自己的容器里保存请求日志，位置是 `/work/data/request-logs/<请求ID>/`。界面上有对应开关：插件 → Claude Code → 设置 → 部署与运行 → 账号容器 →「请求调试日志」，每个账号一个开关。

- **开关只有两档。**
  - 开：完整记录（默认就是开）。
  - 关：停止记录，并删除这个账号已有的全部日志。
  - 开关状态存在 Worker 数据卷里：有 `request-logs.disabled` 文件就是关。
- **记录内容**：

| 文件 | 内容 | 是否含对话正文 |
|---|---|---|
| `metadata.json` | 请求 ID、路径、模型、是否流式、消息数和每条的块类型与字节数、请求体大小和 sha256、状态码、阶段、耗时、错误类型和截断后的错误信息、日志状态 | 否 |
| `events.jsonl` | 处理过程事件：请求类别、模式、内容策略逐字段诊断、CLI 错误码、历史提交等 | 基本没有。例外是 `web_search_output`（搜索结果原文）和几处 `err.Error()` 文本 |
| `request-headers.json`、`response-headers.json` | 请求头和响应头。`Authorization`、`X-Api-Key`、`Cookie` 等已遮蔽 | 否 |
| `request.body` | 客户端的完整请求体 | **是** |
| `build-components.json` | 交给 CLI 的构建组件 | **是** |
| `response.body` | 完整响应（包括 SSE） | **是** |
| `cli-stdout.jsonl`、`history-native.jsonl`、`history-prepared.jsonl`、`history.json`、`mod-config.json`、`resource-*.json` | CLI 原始输出、会话历史快照、资源请求 | **是** |

- **上限**：保留 24 小时；单个请求最多 64 MiB；全部日志软上限 512 MiB。超出部分不再写入，记录被标记为截断，请求本身照常处理。
- **线上现状**（只读查看，2026-10-23）：运行中的账号都开着。21 号约 10 MB，31 号 8.8 MB（96 个请求），32、33 号各几百 KB。

问题在于，排查最常用的是元数据和事件，而默认开启的完整记录把用户的全部对话明文保存了 24 小时。

## 2. 三个级别

| 级别 | 记录 | 用途 |
|---|---|---|
| **关闭** | 什么都不记 | 不需要排查的账号 |
| **摘要**（默认） | `metadata.json`、`events.jsonl`、请求头和响应头（遮蔽同现在）。不写任何对话正文 | 日常排查：状态码、耗时、请求类别、注入等级的逐字段诊断、错误码 |
| **完整** | 摘要的全部内容，加上请求体、响应体、构建组件、CLI 输出、历史快照，和现在一样 | 复现具体问题时临时打开 |

**完整级别自动到期。** 打开时必须选时长（1 小时、4 小时或 24 小时），到期后 Worker 自动回到摘要级别，避免忘了关、一直保存对话。已经记下的完整日志按保留期过期，不会立刻删除。

**摘要级别不能带正文**，所以下面几处要改：

- `web_search_output` 事件现在带搜索结果原文。摘要级别改为只记结构（结果条数、各条 URL 的域名、字节数），原文只在完整级别记。
- 其他事件按“是否含正文”逐个归类。含正文的改用一个新方法 `traceContent`，它只在完整级别写入；其余保持 `trace`。归类表随实现一起提交，加一条测试：在摘要级别跑一遍矩阵，检查日志目录里不出现请求中的标记文本。
- `metadata.json` 和事件里的错误信息仍保留最多 256 个字符。这些文字来自 CLI 或上游的报错，排查离不开。少数上游报错可能引用请求里的片段，这一点在界面说明里写明。

## 3. 保留和上限

两个级别分开计算：

| | 摘要 | 完整 |
|---|---|---|
| 保留 | 7 天 | 24 小时（不变） |
| 总预算 | 128 MiB | 512 MiB（不变） |
| 单请求 | 256 KiB（元数据和事件） | 64 MiB（不变） |

单个摘要记录大约 2–10 KB，128 MiB 能存下一万条以上，7 天对当前流量足够。超出预算时删除最旧的记录。完整级别过期时，只删正文文件，同一请求的摘要文件按摘要的保留期处理。

## 4. Worker 接口

`/admin/request-logs`，经核心和控制器转发，路径不变：

```text
GET  → {"level":"summary","full_until":null,"levels":["off","summary","full"],
        "limits":{"summary":{"retention_hours":168,"storage_budget_bytes":134217728,"per_request_limit_bytes":262144},
                  "full":{"retention_hours":24,"storage_budget_bytes":536870912,"per_request_limit_bytes":67108864}},
        "usage":{"summary_bytes":…,"full_bytes":…,"requests":…},
        "enabled":true}
PUT  ← {"level":"off"} | {"level":"summary"} | {"level":"full","full_for_hours":1|4|24} | {"clear_full":true} | 旧的 {"enabled":bool}
```

- **级别存放**：存在数据卷的 `request-logs.json` 文件里，格式是 `{"level", "full_until"}`。Worker 重启后照常生效，到期判断在每个请求开始时做。
- **关闭的效果**：和现在一样，立即停止写入，并删除全部日志。
- **从完整降到摘要**：已有的完整日志保留到期。界面上另外提供“删除完整内容”按钮，只删正文文件。
- **兼容旧核心**：
  - 旧核心发 `{"enabled": bool}`：`false` 等于关闭，`true` 等于摘要。
  - GET 响应里保留 `enabled` 字段，摘要和完整都算 `true`。
  - 旧的 `request-logs.disabled` 文件读成“关闭”。
- **兼容旧 Worker**：GET 里没有 `levels` 字段，核心就只给旧开关。
- **新旧判断**：只看 GET 里有没有 `levels`，不另设能力标识。完整级别过期后，GET 当场按摘要报告，`full_until` 为 null；`enabled` 始终等于“级别不是关闭”。

## 5. 核心与界面

**核心**（`server/internal/ccgateway/request_logs.go`）：

- 透传新字段，并校验取值：`level` 只能是三档之一，`full_for_hours` 只能是 1、4、24。
- 每次修改都记审计，写明级别和到期时间。
- 权限不变：`settings:manage`，或者有该账号的编辑权限。
- 日志内容仍然不经过核心。

**界面**（`AccountRuntimes.vue` 的“请求调试日志”列）：

```text
请求调试日志
[ 关闭 | 摘要 | 完整 ]   ⓘ
完整：剩余 3 小时 12 分（到期回到摘要）   [删除完整内容]
```

- 选“完整”时弹出选择：1 小时 / 4 小时 / 24 小时，并说明完整级别会保存对话正文。
- ⓘ 里显示两个级别各自的保留期、预算和当前占用。
- 旧 Worker 仍显示原来的开关。

不在这次范围内：在界面里查看日志内容。之后要做的话，从摘要级别开始，单独写设计。

## 9. Worker 实现（2026-10-23）

- **级别状态**：`requestLogStore` 新增 `level`、`fullUntil`，状态写在 `request-logs.json`。
  - 关闭时同时写旧标记 `request-logs.disabled`，回滚到旧 Worker 后仍然是关闭。
  - 每个请求开始时由 `captureContent()` 决定是否记录正文；完整级别到期时，在这里自动回到摘要并写盘。
  - 测试和内嵌用的 store 没有级别（`level == ""`），这时照旧记录全部。
- **按请求区分**：`requestDiagnostic.summaryOnly` 为真时，只写 `summaryFiles` 里的四个文件，其余文件名一律视为正文。`response.body` 也不打开。单请求上限是 256 KiB。
- **事件**：摘要级别下，`trace` 把 detail 里每个字符串截到 256 字节。`traceContent` 用于三类事件：`web_search_output`、`mod_attachment`、`mod_tool_call`。完整级别写原文，摘要级别只写结构，例如字节数和类型。
- **清理**：同一个请求的正文文件和摘要文件按各自的保留期和预算分别清理。请求开始时最多每分钟清理一次，维护循环也是每分钟一次。
- **接口**：PUT 只接受第 4 节列出的五种形式之一，键集不对或取值不对都返回 400。GET 在新形状之外，仍带旧的四个顶层字段。
- **测试**：
  - 新增 `request_log_levels_test.go`，覆盖：默认级别与旧标记、摘要级别不含任何正文、完整级别到期后回到摘要并写盘、PUT 校验、清除正文时保留摘要、按级别各自的预算。
  - 原有测试按新语义调整了两处：过 24 小时只删正文、7 天删整个请求；关闭会写入旧标记。
  - engine 全部测试通过。
- **docker 实测**（ovh 断网容器，真实 CLI v21，新 Worker）：用默认级别跑了 21 个请求，涵盖 build、direct、四个注入等级和 CC 请求。日志目录里只有四种摘要文件；客户端提示词、系统提示词、环境附件、OAuth 令牌和网关密钥一处都没有出现。
