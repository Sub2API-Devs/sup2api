# CCGateway 控制器与共享 Xray 出口迁移方案

实施状态（2026-10-15）：控制器与共享出口首版已部署，8 个运行环境已迁移并就绪；见[迁移验收记录](ccgateway-migration/evidence/xray-migration-20261015.json)。首版以 CONTRACTS 第 57 节为准：DNS 不缓存，网络池修改先回迁，旧 egress 停止保留；严格每请求版本屏障仍不在本轮范围。

日期：2026-10-15。状态：已实施；账号 21、22、24–29 已迁移，20、23 保持停用。

第一阶段以 CCGateway 控制器为主：保留核心已有代理下发合同，控制器增加共享 Xray 后端，逐账号将默认网关从独立 sing-box 切到共享出口。旧后端保留用于共存和回滚。

## 1. 修改范围

| 部分 | 第一阶段安排 |
| --- | --- |
| 控制器 manager | 按持久 backend 分派 apply、activate、status、block、delete、重启恢复 |
| 控制器网络模块 | 共享网关、源 IP 身份校验、TPROXY、DNS、端点白名单 |
| 新增共享出口模块 | Xray 管理 API、完整路由快照、事务恢复、引用计数和排空回收 |
| 出口镜像及发布包 | 固定版本 Xray、DNS 组件、探针；与旧 sing-box 镜像共存 |
| 迁移工具 | 使用控制器现有鉴权体系下的私有操作，提供预检、迁移、状态和回滚 |
| 核心与前端 | 复用保存、生命周期、配置下发、ready/revision；只修复兼容测试发现的必要问题 |
| Worker、CLI、Mod | 保持代码和内容协议；首次迁移允许停止并启动原 app 容器 |

新数据库表、每请求出口头、Worker 准入接口和前端迁移面板均不作为首版依赖。发布包可携带新组件，核心最低版本以实际合同及兼容测试确定，不因增加出口实现而自动抬高。

## 2. 后端选择和混合运行

控制器按 runtime_key 持久保存 `egress_backend = per_account_singbox | shared_xray`。已有记录缺少该字段时按旧后端解释，新建环境首版也默认旧后端，显式迁移成功才提交共享状态。

普通核心下发中的代理、直连、启停、授权仍然有效；缺少 backend 字段不能覆盖已迁移状态。迁移另存目标后端和执行阶段，恢复时先处理未完成事务，不能只按最终 backend 重建路由。

```text
账号 A app → A 内部网 → A sing-box → 代理 A
账号 B app → B 内部网 → 共享 Xray → 代理 B
账号 C app → C 内部网 → 共享 Xray → 显式直连
```

共享出口在各账号内部网有不同网关 IP，另接共享 uplink。保留 app 容器、内部网络和源 IP，不把所有 app 并入同一业务网络。

## 3. 控制器实现顺序

路径相对 `next/plugins/ccgateway/companions/`。

1. 从 `controller/manager.py`、`network.py` 提取旧出口操作边界，先保持旧行为并跑原有测试。
2. 新增共享出口实现，管理固定版本 API、来源映射、DNS、防火墙和持久快照；全局表写入串行化，删除单账号只释放自己的引用。
3. 修改 `public` / `connection`：共享账号不再要求独立 egress 存在，而要求共享服务、账号映射、网络身份和 revision 均验证通过；对核心保持原状态合同。
4. 修改 apply、block、delete、草稿清理、授权重建及 Worker 更新后的激活，全部读取 backend。逐账号更新不能误重启或误删共享服务。
5. 实现私有迁移操作和恢复日志。迁移、配置变更、删除、Worker 更新使用相同运行环境操作锁，锁顺序固定；HTTP 超时允许幂等重试。
6. 验证新控制器配现有核心/Worker，再发布共存版本；升级控制器本身不迁移任何账号。

共享出口和 DNS 组件是本次必要开发。仅替换镜像会破坏原有配置生成、健康检查和资源清理逻辑。

## 4. 上线前预检

预检只读输出账号清单和阻塞原因，不修改网络。

- 记录控制器、核心、Worker、CLI、出口镜像和 Xray 的实际版本/摘要，确认旧镜像、配置及恢复工具可用。
- 保存 app ID、运行状态、挂载、内部网络 ID/IP、网关、DNS、nftables、旧 egress 和 uplink。
- 验证当前代理及 DNS/业务路径，检查共享出口地址与 Docker/宿主机网段无冲突。
- 确认使用控制器隧道。存在绕过控制器直连 Worker 的入口时，先关闭该入口或暂不支持迁移。
- 通过认证 HTTP/HTTPS/SOCKS5、DNS、恢复和并发测试；TCP PoC 不替代这些门禁。

停用、停止和无容器账号默认跳过，不为完成迁移清单而启用或创建。可在以后显式启动时另行迁移。

## 5. 单账号切换

首次迁移采用账号维护窗口，允许短暂不可用；默认一次一个账号。迁移后修改代理使用[热更新链路](CCGATEWAY-XRAY-PROXY-SYNC.md)，两者中断边界不同。

| 步骤 | 控制器动作 | 完成条件 |
| --- | --- | --- |
| 1 回滚锚点 | 保存原配置字节、身份、运行状态和旧资源引用，持久记录操作 ID | 材料完整，身份未变 |
| 2 准备路径 | 共享出口接入内部网，分配不同于旧 egress 的新网关 IP，准备映射和 DNS | 私有测试通过，未改 app 路由 |
| 3 进入维护 | 标记迁移中，清除在线就绪标记，拒绝新隧道，串行处理冲突操作 | 非 ready，不改管理员 schedulable |
| 4 等待空闲 | 限时检查活动 CLI 和出口连接 | 仍繁忙则撤销维护、稍后重试，不默认强杀长任务 |
| 5 停止原 app | 停止并确认原 app 已停止，保留容器与挂载 | 旧隧道及网络连接结束 |
| 6 安装配置 | 保存目标网关、DNS、待恢复规则，保留旧 egress | 日志可明确续做或回滚 |
| 7 启动及激活 | 启动同一 app，按共享分支设置网关和网络策略 | ID/数据不变，验证前保持非 ready |
| 8 验证提交 | 从 app 网络验证 DNS、TLS、目标出口及 Worker 健康，提交 backend 和 applied revision | 按现有 ready/revision 恢复服务 |
| 9 观察 | 灰度验证真实模型、SSE、工具和续聊，保留旧资源 | 观察通过后扩大范围 |

空闲检查与停止之间可能有旧复用隧道送入新请求，首版不宣称绝对无中断。维护期间少量请求可能失败，不能自动重放已执行的模型请求。严格零打断需要 Worker 原子停止接收新运行的能力，另行设计。

app 启动时仍只连接 internal 网络，验证前控制器不开放新隧道。必须测试 app 自动启动任务和 DNS 无绕路，不能仅靠 ready 字段隔离网络。

DNS 若为单文件 bind mount，写入必须让容器看到新内容；不能只原子替换宿主机路径而让挂载仍持有旧 inode。验收读取容器内实际文件，回滚恢复原字节。

## 6. 回滚和崩溃恢复

提交前失败：保持非 ready，停止正在切换的原 app，恢复旧网关、DNS、防火墙和 egress，再启动同一 app、验证旧路径。成功后回旧 backend；失败保留错误和材料，不标记 ready。

提交后回迁：执行反向维护窗口，确认旧镜像/配置/网络可恢复后，停止原 app、恢复旧路径、启动并验证。不得借用其他账号代理，也不能将代理故障解释为直连授权。

若核心在迁移期间保存了新代理，回滚只恢复后端，随后仍须应用核心最新期望；不能把锚点中的旧代理标成新目标已生效。revision 不同则保持待同步，由现有生命周期重新下发并收敛。

| 中断位置 | 恢复规则 |
| --- | --- |
| 仅准备共享资源，app 未切换 | 撤销本账号未提交引用，核验旧后端后恢复服务 |
| app 已停止，backend 未提交 | 根据日志恢复旧配置并启动原先运行的 app，或明确续做同一操作 |
| 新网关已安装，验证未完成 | 非 ready，重新探测，失败回滚 |
| backend 已提交，响应丢失 | 核验实际路径并返回同一操作结果，不重复停止/启动 |
| 共享服务重启 | 重建全体持久映射并逐账号验证，不沿用旧 boot 的 ready |

恢复只启动迁移前运行且业务仍允许运行的账号；停用、删除、手动停止不能被恢复任务覆盖。相关操作通过同一运行环境锁协调。

旧控制器不认识共享状态，不能直接替换新控制器。降级前先回迁全部共享账号并清空未完成事务；升级工具须在旧版本替换前检查，否则保留新控制器处理恢复。

## 7. 灰度和资源回收

顺序：隔离测试 → 升级控制器但保持旧后端 → 测试环境迁移/回滚 → 一个选定账号 → 小批量 → 其余适合迁移的账号。失败时停止扩大，只处理相关账号，不重启整个共享 Xray。

首批建议至少观察 24 小时并完成回滚演练，再回收旧 egress 及独占 uplink。该时长是发布建议，不是已经完成的观察。账号内部网和 app 数据卷保留。

GC 同时检查账号引用、在途事务、回滚保留及旧连接引用；全部归零才能删除共享出口或 uplink。迁移中保留的旧 egress 不能被孤儿清理误删。

## 8. 完成标准

须具备共存测试、现有前端改代理自动同步、单账号迁移和反向回滚、各组件重启恢复、容器 ID/数据保留证据，以及真实模型普通回复、流式、工具和续聊验证。

执行报告列明维护期间请求失败情况、仍在旧后端的账号和旧资源回收时间。控制器接入及 8 个生产运行环境迁移已完成，详见[验收记录](ccgateway-migration/evidence/xray-migration-20261015.json)。旧出口容器已停止并保留，尚未执行观察期后的删除。
