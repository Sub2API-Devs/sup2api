# 外壳托管升级实现与验证

日期：2026-10-01。分支：`feat/next-platform`。本轮代码仍在工作区，未提交、推送或部署到业务环境。

## 已实现

- 独立 `runtime-contract` / `shell` 模块：签名清单、不可变制品、安全解包、原子切换、Linux 进程管理及恢复日志。
- mTLS 单跳代理：本地与对端模式、路由/核心启动身份校验、SSE/WebSocket、禁止请求重放、可信代理头处理。
- 核心候选、准备、准入、排空和关闭；HTTP、业务任务与插件协调分别控制。首次 bootstrap 仅例外允许准备期的插件激活，且首次准入完成后不再重复导入内建插件。
- PG 持久升级步骤、Redis 协调与节点互斥、连续心跳、暂停/继续、兼容性检查及失败隔离。
- 受限回退：仅回到最近已完成的集群基线；先通过所有节点操作锁屏障，再创建新恢复计划。按健康承接节点安排顺序，继承已执行路由，拒绝不兼容版本，晚到结果不污染旧计划历史。
- 核心发布签名工具、管理页面、RBAC/二次验证、CLI、独立外壳镜像、两节点 Compose 示例和 CI 检查。

插件保持独立发布。核心准备与准入检查实际批准且兼容的插件状态；核心升级不把随包内建版本重新覆盖到集群。

部署与运维入口：[`deploy/shell/README.md`](../../../deploy/shell/README.md)。协议：CONTRACTS §33。完整目标设计及尚未实现部分：[`SHELL-MANAGED-UPDATES.md`](../../SHELL-MANAGED-UPDATES.md)。

## 本轮发现并处理的问题

- 准入记录刷新被旧 watcher 误当撤销；HTTP 尚未成功监听就进入 prepared。
- 显式首装中，插件协调被准入门关闭导致互相等待。
- SIGKILL 残留 socket、插件子进程及新转为僵尸的进程妨碍恢复。
- 心跳刷新可能覆盖刚完成的本地路由切换。
- 永久坏版本无法退出原失败计划；已用受限恢复计划补齐操作闭环。
- 重复 `-bootstrap` 可能重新导入内建插件；已按首次准入状态限制。
- Shell 与 Core 环境变量命名不同可能导致核心使用错误的数据源；核心现在显式使用外壳解析后的同集群 PG/Redis 配置。

首轮跨版本探针选用了 R2 才新增的管理接口，将 R1 的 404 误计为失败；改为两版本共有接口，保留零异常断言。真实插件初次测试包只带 amd64，被生产双架构校验拒绝；补齐 arm64，未关闭生产校验。

## 当前边界

仅支持 schema、Cluster/Task 协议和 Host API 契约不变的兼容滚动升级及上述受限回退。跨 schema 维护迁移、自动选举升级主节点、任意目标强制回退、外壳自身在线替换、节点级 SQL 函数权限隔离尚未实现。未知旧进程仍存活时拒绝自动另起核心。

此前 30 项完整业务 E2E 是同一核心版本的双节点测试，本次未将其冒充跨版本结果，也未重新执行整套旧 E2E。实际付费上游和跨版本下完整计费/SSE业务请求仍不在这份验证记录的通过范围内。
