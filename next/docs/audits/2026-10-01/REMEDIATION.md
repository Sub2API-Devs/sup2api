## 核心与插件的职责

PostgreSQL 保存身份、持久状态、事务和幂等账本；Redis 提供短期执行权、并发槽和实时限额。共享存储不会自动使多步骤读写成为原子操作，也不会自动撤销失去执行权的节点。

核心为异步任务提供统一提交登记、归属校验、账号绑定、轮询认领、带版本约束的结果写入和计费。插件声明端点、解释上游请求和响应；不自行连接 Redis、不在 `Init` 启动轮询、不把“账号排名”当成任务归属约束。

## 整改对应

| 审计项 | 处理方式 |
|---|---|
| F01 / F02 任务归属与账号 | 核心生成公开任务 ID，保存认证归属及原账号；客户端查询只读 PG 快照，核心领取任务并固定账号轮询。旧裸 ID 只允许从可信核心账务导入 |
| F03 / F04 并发槽 | 持有表以完整槽键和租约成员隔离，每次获取都有新成员；续期只延长现存成员，失去槽位或本地有效期结束即取消请求 |

| F06 卸载与并发启用 | 持久卸载屏障、进程启动登记及实际停止确认；所有目标确认前不删 schema。新增卸载状态与确认进程实际终止的管理 API，校验权限、step-up、epoch、目标及当前存活情况；同事务审计，确认后仍须显式重试卸载 |
| F07 发布协调者过期 | 失败收尾同时校验 coordinator、row_version 和有效租约，旧协调者不能覆盖新发布状态 |
| F08 刷新令牌重放 | 发放、旋转、重放撤销和退出按用户父行串行，避免漏掉并发产生的后代令牌 |
| F09 分组集合替换 | 同一用户的整组 DELETE/INSERT 在用户父行锁内完成，防止两份替换合并 |
| F10 API Key 旧身份 | 每次认证以 PG 联表读取为准，取消可被迟到读取重新填入的 Redis 身份缓存；代价是每个请求多一次权威数据库查询 |
| F11 / F12 账号限额和冷却 | Redis Lua 原子准入 RPM/SPM；冷却原子取更长期限，首次进入冷却只返回一次触发标记。TPM/TPD 仍按记录的用量累计，不提供请求前严格 token 预留 |
| F13 配置部分更新 | 核心通用 UpdateSettingJSONTx 在 settings 行锁内合并最新配置，覆盖首次创建和并发 patch |
| F14 本地缓存 | 失效代次约束迟到读取，防止旧价格、代理、路由等缓存跨失效回填；这不等于广播绝不丢失，仍保留周期刷新兜底 |
| F15 moderation | 自动封禁、人工操作、清理统一锁持久用户父行；插件通过宿主提供的 schema / PG 事务完成 |
| F16 volcengine 素材 | 同一资源的上游操作与索引更新按 PG 资源行锁排序；创建失败有补偿。上游与 PG 仍不构成跨系统原子事务 |
| F17 / F18 关停与用量 | SIGTERM 后就绪检查失败并拒绝新请求，等待处理器和异步用量工作；溢出持久化加入停止屏障；Compose 停止宽限改为 180 秒 |
| F19 内置插件收敛 | 竞争锁失败或单个安装失败会重试；启动就绪等待内置版本持久化与本地实例收敛 |
| F20 跨节点静态资源 | 插件按已批准且未撤销的不可变版本包从 PG 读取；控制台通过 PG 共享哈希资源，拒绝同 URL 内容冲突，就绪检查等待发布；按构建租约、最近 7 天及最近 3 个构建保留，容量不足拒绝新发布 |

复核补充 F21：B 节点时钟快 20 秒时，旧实现会删掉刚心跳的 A 节点及其活跃槽位，A 请求尚未取消而 B 已再次取得并发上限为 1 的账号。现已将心跳、存活筛选、槽位及账号限额的共享时间改为 Redis 时间，保留本地单调计时的取消期限。定向回归验证了活跃槽不被误回收、第二个请求仍被拒绝。

新任务能力还增加 Host API 2 握手检查。仅依靠上传节点的 manifest 校验不足以保护其他节点从共享 PG 加载插件；SDK 在初始化前拒绝旧宿主。此检查不能改变旧核心后台程序，发布与回退必须遵守 CONTRACTS §28.4，不能在产生托管任务后混跑旧核心。

新增核心迁移为 `0016_plugin_uninstalls.sql`、`0017_async_tasks.sql`、`0018_web_assets.sql`。托管任务复核还覆盖了无预扣任务的即时计费、免费任务、注册失败回滚、过期租约与迟到结算、旧账务导入以及终态快照一致性。没有把“预扣事务回滚必然遗留 reserved 钱款”当作已证实问题：旧路径中的预扣、用量和待核对记录原本就在同一事务；整改针对已复现的具体路径。

## 用户授权的后续：统一调度与单次 Poll

用户在首轮整改后确认“核心统一调度，插件执行一次查询并通过核心代理出网”，已按此方向继续实施。契约见 [CONTRACTS §30](../../CONTRACTS.md#30-统一后台执行与单次-poll2026-10-01)。本节之前的测试结果保留为首轮证据，不代替本次接口调整的重新验证。

主要变更：核心增加共享后台 Executor，jobs 和 reconcile 使用统一的准入、并发、超时、取消、租约生命周期与关闭屏障；保留各自的 cron/PG 认领和账务语义。SDK 增加 Poller、ExecuteHTTP 及 Host API 3 门禁；volcengine 0.9.0 通过一次 Poll 完成请求和解析。旧接口兼容保留，在线账号策略和插件本地缓存/批写不迁入后台队列。

专用 HTTP 能力绑定具体插件进程、本次执行和原账号，一次 Poll 最多使用一次；调用结束撤销并等待在途 HTTP 结束。代理、SSRF、限额、响应上限和网络结果检查由核心执行。它不会把插件既有的通用 Egress 权限自动变成任务账号限额。

此步骤的 SDK 完整 test/vet/build 通过，服务端编译与定向真实 PG 回归通过。它仍不是下面最终 Execute / Monitor 代码的全量验收，尚未提交、推送或部署。

首轮完整命令仍返回失败，不能将这些局部通过写成全套通过。它实际暴露并推动修复了以下问题：
