# 插件资源（共享 / 独享）与隔离审查（2026-10-09）

用户原则：插件向核心申请的一切都是**资源**，分**共享资源**（可多方声明，如账号支持的端点、内置平台 anthropic/openai/gemini）与**独享资源**（不能重复分配，如账号类型、配置前缀）。插件保存系统配置须经核心 API、使用核心分配的前缀（如 `settings.<plugin>`）。安装、更新插件时要严格校验所有申请的资源。

四个只读 agent 并行审查：资源清单、安装/更新冲突校验、运行时宿主 API 隔离、平台/账号类型/端点语义。部分结论用临时测试（testpg）实证，标注“实证”；其余为代码静态确认，标注“静态”。

## 一、资源总表

| 资源 | 应为 | 现状 | 缺口 |
|---|---|---|---|
| 插件 key | 独享（根命名空间） | DB 主键 + 发布者归属检查 | 卸载后归属释放、可被他人重新认领（P1-4）；无保留 key 列表（P1-5） |
| 新平台 ID | 独享 | 上传时跨插件检查、不能用内置 ID；发布时兜底按 key 字母序 | 只在上传检查一次（P2-2）；兜底应按先占用 |
| 内置平台 | 共享 | 只能引用、不能重新声明 | 符合 |
| 网关端点路径 / 协议 | 定义独享，引用共享 | 上传时与内置、其他插件做重叠检测；协议须 `<平台>.<名>` | 保留表漏了核心实际占用的 `/v1/files`、`/v1/skills`、控制台路径（P1-6，实证可劫持控制台） |
| 账号类型 | 独享 | 身份为（插件 key, 类型 ID），插件内唯一；全链路按二者联合查询，**无串号**（静态 + 现有测试） | 契约需写明身份是（插件, 类型）；用量/账号列表 `account_type` 过滤未带插件 key（低） |
| 账号支持的平台/端点 | 共享 | 多插件可声明同一平台 | 异步任务端点、WebSocket 端点的例外未写进契约 |
| 粘性规则名 | 独享 | **安装期不检查**；同步时先到先得、后者静默跳过；与内置同名被遮蔽；同插件两平台同名后者覆盖；`match.protocols` 可指向别的平台；Redis 键无插件前缀（实证） | P2-1 |
| 系统配置 | 独享（核心分配前缀） | **没有任何插件写配置的 Host API**；`settings` 表扁平无归属；`ccgateway_remote` 由核心代码写死；`config` 权限有名无实现 | P3-1 |
| 插件自有配置 | 独享 | `plugins.config_enc`，AAD 绑定 key，管理员写、插件只读 | 符合 |
| 数据库模式 | 独享 | `plg_<key>` + 独立角色 | 宿主无 CREATEROLE 时**静默降级为宿主角色**，可改核心表；同名角色被接管（P1-7） |
| KV / 锁 / 广播 / 权限名 / 插件路由 / UI 区块与资源 | 独享 | 宿主按调用者强制加前缀 | 符合（但前提被 P0 绕开） |
| 钩子 / 调度 rank / 事件订阅 / 任务 / 出站域名 | 共享 | 按 order 与插件 key 排序 | rank 能改写其他插件账号的调度参数（按设计，靠高风险授权） |
| 用量 facts 键 / creationGroup | 待定 | 全局命名空间，无跨插件校验 | 待定 |

## 二、问题与修复优先级

### P0 隔离前提（不修则一切前缀都可绕开）（2026-10-10 已修并上线，CONTRACTS §54；插件与核心同 UID 仍未根治）
1. **插件与核心同一 UID**（静态，需 Linux 实测）：插件可读 `/proc/<核心>/environ` 拿到 master key、DB 密码、JWT 密钥；可连外壳管理 socket（无认证）。修：每插件独立 UID 或用户/PID 命名空间；核心启动后清除敏感环境变量并 `PR_SET_DUMPABLE=0`。
2. **插件可冒充其他插件调用 HostService**（静态，需实测）：go-plugin 宿主 broker socket 在共享 `/tmp`，无 mTLS，身份只按连入的 socket 判定；可读他人账号明文凭据、借 payment 身份加余额、取他人 DB 密码。修：`UnixSocketConfig` 私有 0700 目录 + AutoMTLS。
3. **出站默认可连私网、Redis 无密码**（静态）：所有插件都有出站隧道，`allow_all` 时放行私网，可直连 `redis:6379` 读写他人 KV、抢锁、改粘性绑定、伪造广播。修：Redis 加密码；无 `net` 授权禁止出站；任何策略都不放行私网/集群地址。

### P1 独享资源分配与归属（2026-10-10 已修，CONTRACTS §55；P1-7 随 P0 完成，§54）
4. **卸载后同 key 被其他发布者认领，继承账号、明文凭据、`plg_<key>` 数据**（实证）。修：卸载保留 key→发布者归属（墓碑）；重装须同发布者，或同意页显式列出将接管的账号并另行确认；凭据 AAD 加入发布者 ID。
5. **第三方上传（无需批准）即可抢占后续内置插件的 key 或平台，节点永久不健康**（实证）。修：保留 key / 平台 ID 列表（内置插件全集）；未批准版本不占用独享资源。
6. **核心路径保留表不全**（实证）：插件可申请 `GET /assets/*rest` 等，启用后控制台不可用；`/v1/files`、`/v1/skills` 被核心先截走。修：保留表由核心实际注册的路由生成，并加单元测试保证一致。
7. **DB 角色隔离静默降级**（静态）：修：无法隔离时拒绝安装需要 `db.schema` 的插件，而不是降级；不接管已存在的同名角色。

### P2 校验时机与规则
1. **粘性规则名纳入独享资源**（实证）：安装期跨插件、跨内置检查；清单内全局去重；`match.protocols` 只能是本插件平台的协议；Redis 键加来源前缀。
2. **冲突只在上传时检查一次**（实证）：批准、启用、升级、核心升级后（发布新代时）都重新校验；冲突时插件状态改为异常并在界面提示，不再只打日志。
3. 未批准 / 已删除的版本不占用资源（2026-10-10 随 P1-5 完成：上传只比对已批准版本，批准时复查）；兜底按先占用而非 key 字母序。
4. 用量 API、账号列表的类型过滤必须与插件 key 成对；余额 provider 改按账号类型注册。

### P3 系统配置资源化
1. HostService 增加 `SettingsGet/Set/List/Delete`：前缀 `settings.<plugin_key>.` 由宿主按调用者强制加上，复用 `config` 权限，带大小上限、审计、row_version、变更通知；敏感值 AAD `plugin-setting:<key>:<name>`。核心自身的键禁止占用 `settings.`、`plugin.` 前缀。清单声明所需配置资源，安装时校验。
2. 把 `ccgateway_remote` 迁到 `settings.ccgateway.*`。

## 三、建议顺序

先在 Linux 容器实测 P0-1、P0-2；确认后按 P0 → P1 → P2 → P3 修。P0 涉及外壳、核心、SDK 与部署（Redis 密码、容器用户），需要一次外壳与核心的联合升级。
