## 摘要

- **最值得先修的是 CLI 版本链路**：成对升级现在发送的是已保存策略里的 `cli_version`，但按钮、确认框和说明文字仍然写死“2.1.304”，并且说“保存 CC 配置会切到 304”。`normalizeRequestPolicy` 改成保留已保存的版本后，这句话已经不成立，控制台也没有任何地方能改目标版本。另外，web 里的 `'2.1.304'` 和核心的 `PinnedCLIVersion` 是两份需要手动同步的常量。
- **账号删除对话框属于核心通用页面，却写进了 CCGateway 专有的文案**（容器、网络、数据卷、“CCGateway 设置的运行环境列表”）。任何声明了 `deletion` 的插件都会看到这段话。
- **父组件通过 ref 调用子组件**：`AccountRuntimes` 用 `retained.value?.load()` 刷新 `RetainedRuntimes`，子组件自己在 `onMounted` 里也会加载，所以首次进入页面会请求两次。
- **CC 版本弹窗留下了旧功能的残余**：轮询分支永远不会触发；`catalog.error` 和 `update_error` 的内容相同，会显示两条一样的红色提示；“定期查看渠道版本”开关在生产环境（CLI 一律固定版本）永远是禁用状态；`cliProfile.pinned` 仍写着“自动更新关闭”。
- **复用与无障碍**：删除对话框重新写了一遍 `crud.ts` 里的 删除→提示→报错 流程，还手工拼接查询串；对话框在请求进行中可以被关掉；待清理列表的标题没有用标题元素，操作列表头为空，对只读用户也显示。新出现的 reason 码 `runtime_not_retained` 和 `cli_version_unavailable` 没有进入 `CCG_REASONS`，中文界面会直接显示英文。
