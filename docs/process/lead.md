# lead 过程文档：AST 扫描、旧版匹配、模块切分、命名、生成

## 1. 提取（tools/extract）

- `restore-bun.cjs`（复用 sup2api 项目里已验证的提取器）：读 ELF 尾部 `---- Bun! ----` 标记前 32 字节的偏移表，定位模块表（每项 52 字节：名字指针、内容指针、loader、编码），按名字写出模块；`import.meta.require` 别名、`/$bunfs/root/` 绝对路径改成相对路径，资源导入加 `with { type }`。输出 `reconstruction.json` 记录 ELF sha256、内嵌 Bun 版本/修订、Node 版本串、每个模块的 sha256 和偏移。
- 结果：2880 模块；与此前在 sup2api `artifacts/claude-2.1.316/linux-restored` 的独立提取逐文件一致（只有 reconstruction.json 的 input 路径不同）。

## 2. AST 扫描（tools/ast/scan.mjs、scan-reference.mjs、lib/features.mjs）

每个顶层语句一条记录：

| 字段 | 含义 |
|---|---|
| `names` | 声明的绑定名（压缩名） |
| `strings` | 字符串字面量与模板文本（3–400 字符） |
| `props` | 成员访问属性名、对象键、类成员名、JSX 属性名 |
| `refs` | 读到的模块级绑定：`=local` 或 `chunk.js\|导出名` |
| `exported` | 本 chunk 的导出名 |

选择这些特征的理由：压缩只改绑定名，字符串和属性名原样保留，是两个版本之间最稳定的指纹。旧版 TS 用同一个特征提取器（跳过类型节点），保证可比。

数据：316 有 81,667 个顶层声明（50 MB），扫描约 20 秒；旧版 12,938 个顶层声明，扫描约 2 分 20 秒（TS 解析慢）。

## 3. 一方匹配（tools/ast/match.mjs）

1. **指纹**：特征权重 = IDF（以 316 全量为语料），字符串 ×1，属性名 ×0.55，出现在 400 个以上声明里的特征丢弃；相似度 = 加权 Dice。316 侧总权重 <4 的声明不参与（特征太少）。接受条件：互为最佳且 ≥0.3，或单向最佳 ≥0.75。
2. **调用图传播**：已匹配对 (d, r) 的未匹配邻居（被调用者、调用者两个方向）互相提议配对；接受条件：≥2 个独立见证，或 1 个见证 + 指纹 ≥0.15；按见证数、分数排序，冲突先到先得，迭代到不动点。
   - 第一版用"唯一候选即匹配"，抽查发现错配（恒等函数 `b` 配成 `shouldUseSessionMemoryCompaction`），已改。
3. **布局插值**：同一 chunk 内夹在同一旧版文件两个声明之间的未匹配声明归该文件。

结果（第一版）：指纹 8,419；传播后 9,138；有文件归属 16,506；触及旧版 1,711 / 1,902 个文件。

## 4. 关键发现：Bun 按顶层语句拆 chunk

同一个旧版文件的声明出现在多个 chunk（1,711 个文件中 728 个跨 chunk；如 `bootstrap/state.ts` 595 个声明在 chunk-ndmse9kj、26 个在 chunk-e6aww6q8）。这与 esbuild 的代码拆分一致：拆分单位是顶层语句（part），按入口可达性分配到 chunk。推论：

- 阅读树按"归属文件"把各 chunk 里的部分重新聚合，而不是按 chunk 切段；
- 同一 chunk 内同一文件的语句仍是连续的，所以布局插值成立；
- `runnable/` 保持 chunk 布局（这是 Bun 实际执行的结构）。

## 5. 模块切分（tools/segment/segment.mjs）

优先级：显式放置（`naming/placement*.json`）> 第三方/运行时（vendor 成员）> 一方匹配 > 布局 > 亲和（与已归属声明相邻、且使用边多数指向该文件）> 剩余按 chunk 连续段归 `_unattributed/`。

第一次运行（尚无第三方数据）：7,201 个模块；一方 1,711 个模块 19,524 个声明 10.5 MB；未归属 62,143 个声明 28.4 MB（预计大部分是第三方）。

## 6. 旧版命名（tools/naming/reference-names.mjs）

对每个匹配对：

- 顶层名：直接取旧版声明名（跳过 React Compiler 生成的 `_tempN`）。
- 参数：两边都是函数且参数个数相同时按位置取名（解构参数跳过）。
- 局部变量：把函数体内绑定声明按出现顺序转成"形状签名"（声明方式 + 初始化表达式形状：调用的方法名/参数个数/字符串参数、成员属性名、字面量值、解构的键名、for-of 的迭代对象……），两边做 LCS 对齐；签名相同且不平凡（或平凡但两边都唯一）才取名。

结果：8,142 个顶层名、5,328 个参数名、17,439 个局部名，约 22 秒。置信度：指纹匹配 0.5+score/2（上限 0.99），参数 ×0.9，局部 ×0.8。

发现：旧版源码里已经有 React Compiler 的产物（`t0`、`_temp`、`opt_0`、`$` 缓存数组），说明泄露的 source map 内容是编译后的 TSX；这些名字照样采用但置信度低。
